# v8.11 Production Evaluation Release — 2026-08-13

> Produced by the "P0 Production Evaluation Integrity Repair" task. Every result in this
> directory was generated by a fresh, real inference run against the **official production
> checkpoints only** (`shufflenet_v2_layer1_v811d.pth` + `shufflenet_v2_layer2_v811.pth`),
> invoked with explicit, verified checkpoint paths — never a script default. See
> `RELEASE_EVALUATION_MANIFEST.json` for the full machine-readable record (SHA256 of every
> checkpoint, script, and output file; exact command lines; git commit hash; timestamps).

## Why this directory exists

Four evaluation scripts (`eval_v811_gates.py`, `AIGuard/stress_test_v811_pipeline.py`,
`AIGuard/eval_ali_ood_v811.py`, `AIGuard/eval_robustness.py`) previously **silently defaulted
to the superseded `shufflenet_v2_layer1_v811c.pth`** checkpoint when run without explicit
arguments. Two archived files in `results/` (`v811_gates_output.txt`,
`ali_ood_v811_output.txt`) were confirmed to have been generated exactly this way — they
report Layer1c numbers, not v8.11d production numbers, despite filenames that look like
production evidence. Those two files are **left untouched** (not overwritten, not deleted,
not renamed) and remain flagged stale in `docs/releases/v8.11_production/`.

This task fixed the 4 scripts to be **fail-closed** (refuse to run without explicit
`--layer1-weights`/`--layer2-weights`, no fallback of any kind) and re-ran all core
evaluations against the real, hash-verified production checkpoints, writing every result
here — a directory that is never overwritten (each result is uniquely named by weight tag +
date + eval name) and never collides with any pre-existing file.
