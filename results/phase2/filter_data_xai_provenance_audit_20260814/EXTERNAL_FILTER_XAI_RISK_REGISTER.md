## Overall read

The highest-severity, best-evidenced risks (#1, #2, #3, #6) all trace back to one root cause:
**`pipeline.py` has no way to know, at inference time, whether an input image resembles the
self-built training distribution (where every claim tier is earned) or an external
RetouchingFFHQ-style distribution (where only the coarse filter/not-filter decision has any
validated backing).** This is not a flaw introduced by any single component — the classifier,
the artifact sub-classifier, the Grad-CAM++ pipeline, and the templates are each individually
consistent with their own documented evidence tier — the risk is that a single unlabeled input
image gives the system no signal about which tier applies, and it always defaults to speaking
at the fullest tier its currently-hardcoded logic supports (which happens to be tuned for the
self-built family).
